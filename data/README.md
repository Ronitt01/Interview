# Data — provenance, licence, and how to re-download

Nothing in `data/cache/` or `data/hinglish/clips/` is committed. Both are
regenerated by a command, and both commands are recorded here so a reviewer can
reproduce the exact inputs rather than trusting that they existed.

---

## 1. Smart Turn corpus (the training and test data)

**Source** — Hugging Face, `pipecat-ai`:

| dataset | rows | size | role |
|---|---|---|---|
| [`pipecat-ai/smart-turn-data-v3.2-train`](https://huggingface.co/datasets/pipecat-ai/smart-turn-data-v3.2-train) | 270,946 | 41.4 GB | training + validation |
| [`pipecat-ai/smart-turn-data-v3.1-test`](https://huggingface.co/datasets/pipecat-ai/smart-turn-data-v3.1-test) | 31,473 | 4.3 GB | held-out test |

Contributors credited on the dataset cards: the Pipecat team, Liva AI,
Midcentury, and MundoAI. Background noise in some clips comes from Freesound
contributors. Both datasets are published as Parquet with a single `train` split —
the train/test separation is between the two *datasets*, not between splits inside
one, which is why `--split` in our script selects a dataset rather than a split.

**Licence** — check the dataset cards on the Hub before redistributing anything.
This repository redistributes **no audio**: it downloads on demand and caches
locally, and the cache is gitignored.

### Schema

| column | type | notes |
|---|---|---|
| `audio` | audio | decoded by us via soundfile, not by `datasets` — see below |
| `audioduration` | float | 0.24 – 32.6 s across the two datasets |
| `id` | string | 36-char UUID, **one per clip** — not a speaker id |
| `language` | string | 23 values, including `hin`, `ben`, `mar` |
| `endpoint_bool` | bool | **the label.** True = the speaker has finished their turn |
| `midfiller` | bool or null | filler mid-utterance. Tri-state — `null` means un-annotated |
| `endfiller` | bool or null | trailing filler. `True` implies `endpoint_bool` is False |
| `synthetic` | bool | TTS-generated rather than human-recorded |
| `dataset` | string | source corpus, ~11–12 values. **Our grouping key for splits** |
| `spoken_text` | string | null throughout the rows we sampled |

### Two schema facts that shape the whole project

**There is no speaker identifier.** `id` is a per-clip UUID — verified as 1,200
unique values across 1,200 rows. A speaker-aware split is therefore impossible.
Splits are grouped by `dataset` instead, and the report states the residual risk
rather than claiming a clean split.

**`endfiller=True` has a positive rate of 0.000** across 302 sampled clips. A
trailing filler never marks a turn end. The corpus has pre-labelled the exact
false-interruption trap, which is what the per-slice reporting leans on.

### Re-downloading

```bash
# what it would cost, before committing to it
python scripts/prepare_data.py --info

# small slice — proves the whole pipeline in minutes
python scripts/prepare_data.py --split test  --all-languages --max-rows 400
python scripts/prepare_data.py --split train --all-languages --max-rows 1200

# the working subset used for the reported runs
python scripts/prepare_data.py --split train --languages eng hin ben mar --max-rows 40000
python scripts/prepare_data.py --split test  --languages eng hin ben mar

# human-recorded audio only (82% of the corpus is TTS)
python scripts/prepare_data.py --split train --human-only

# everything
python scripts/prepare_data.py --split train --all-languages
```

Every cache writes a `cache_info.json` recording the exact filters, row count,
hours of audio, and skip reasons that produced it — so a result can always be
traced back to the data that made it.

### Cache format

```
data/cache/<split>/
  waves.i16        flat int16 PCM, 16 kHz mono, all clips concatenated
  offsets.npy      int64 start sample per clip
  lengths.npy      int64 sample count per clip
  meta.jsonl       one JSON object per clip (the columns above)
  cache_info.json  provenance: source dataset, filters, counts, skips
```

Read with `src.dataset.WaveCache`. The waveform is memmapped read-only, so
DataLoader workers share the OS page cache instead of duplicating it.

**Why the waveform and not the mel spectrogram** is cached: caching mel would
freeze the window length and the mel configuration, which would make the E2
window sweep impossible. Caching a fixed 8 s window would waste roughly 2× the
disk on a corpus whose median clip is 7.2 s. int16 rather than float32 halves the
size for no measurable cost — the source audio was almost certainly 16-bit
already.

### A note on decoding

`datasets` ≥ 5 routes `Audio` decoding through `torchcodec`, which needs a
matching FFmpeg build and is awkward to install on Windows and on some Colab
images. `src/dataset.py` casts the column to `Audio(decode=False)` and decodes the
raw bytes with `soundfile`. One less native dependency, identical output, and it
is the same decode path the demo uses for uploads.

## 2. Hinglish stress set (hand-authored)

**Source** — this repository. `data/hinglish/phrases.py` holds 44 phrases across
7 categories, written by hand and labelled by hand. Rendered to audio by
**Sarvam AI Bulbul v3** TTS.

```bash
python scripts/synthesize_hinglish.py --dry-run          # list, no API calls
python scripts/synthesize_hinglish.py --pause-variants   # generate (needs SARVAM_API_KEY)
```

Requires `SARVAM_API_KEY` in `.env` and consumes API credits — roughly one short
TTS call per clip. The script resumes from an existing manifest rather than
re-synthesising, and validates speaker names locally before spending anything.

Output: `data/hinglish/clips/*.wav` plus `manifest.jsonl`, one row per clip
carrying the text, speaker, category, label, spliced-pause length, and
`synthetic: true`.

### Why it exists when the corpus already has Hindi

The corpus has **monolingual Hindi**. It has no *code-switched* Hinglish, no
Indian-English accent slice, and no logistics-domain vocabulary — which is where
the shorthand that sounds like a sentence ending actually lives ("POD bhej diya",
"GR number"). Those three gaps are what this set fills.

### Speaker names are model-specific

Bulbul v3 rejects the v2-era names. The valid roster is recorded in
`BULBUL_V3_SPEAKERS` in `phrases.py`; the script checks against it and fails
before making any call, because an invalid name produces a 400 on *every*
request.

### Honesty about synthetic audio

These are TTS clips. Which direction that biases a result **depends on the
detector**, and the usual "TTS is an upper bound" shorthand is wrong here:

- for a **prosody model**, TTS is easier — clean, evenly paced, no disfluent
  timing — so its score is optimistic;
- for a **silence-timer baseline**, TTS is *harder*, because Bulbul emits almost
  no trailing silence after a completed utterance and the baseline's only cue is
  therefore absent. Measured: E0 scores ROC-AUC 0.476 on this set, below chance.

So the set measures whether a detector uses linguistic completion cues rather
than duration of silence. `scripts/eval_hinglish.py` reports it as its own table
and never averages it into the main test numbers.

**What is still missing:** real recorded Hinglish. TTS covers vocabulary,
code-switching and pause placement; it does not reproduce genuine disfluent
timing, overlapping speech, or real room acoustics.

## 3. Silero VAD (the E0b baseline)

Pulled by the `silero-vad` pip package on first use — `src/baselines.py` loads it
lazily, so nothing is downloaded unless E0b actually runs. ~10 MB on disk, MIT
licensed. Used only as a reference detector; it is never trained or fine-tuned
here.
